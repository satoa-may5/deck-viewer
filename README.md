# deck-viewer(デッキメーカー(仮))

手持ちのカード画像からデッキのカード一覧を作れるローカルアプリ。カードは
「カードプール」(弾ごとなどのグループ)単位で登録し、デッキ作成時は1つ以上の
カードプールを参照して手持ち一覧を組み立てる。カードの登録(画像アップロード+
トリミング+情報入力)・編集・削除、横画面で上にデッキ・下に手持ちカード一覧を並べて
クリック/スワイプで追加していくデッキビルダー、グリッド表示の読み取り専用デッキ表示を
備える。ホーム画面は「デッキ」「カードプール」のタブ切り替えで、
どちらも削除・並び替え(ドラッグ、一覧/グリッド表示両対応・デフォルトはグリッド)、
お気に入り登録(★、「お気に入りのみ表示」で絞り込みも可)ができ、デッキはさらに
リネーム・複製もできる。カードプール・デッキにはそれぞれ1枚までサムネイル画像を
指定でき、名前は重複すると自動で「(1)」のように連番が付く。カードにはタイプ
(キャラクター/イベント/フィールド)・必要エナジー・色・パラレルの有無・トリガー
に加え、カード名・レアリティ・消費AP・BP・発生エナジー・
特徴・効果テキストも設定でき、カードプール個別ページ・デッキ作成画面どちらでも
折りたたみ式のフィルターサイドバーからこれらの条件で絞り込める(カード名/効果の
自由テキスト検索も可)。デッキ作成画面には必要エナジー分布・トリガー内訳のグラフに
加えて、初手7枚+マリガンの成功率を厳密計算するマリガンシミュレーターも備える。
完成したデッキは16:9の一覧画像として書き出せるほか、A4に9枚ずつ並べた印刷用
ファイル(TIFF/PNG)を作れる(切り出してプロキシにする用途。プリンターのズレを
補正するキャリブレーション機能付き)。
カードプール・デッキはそれぞれ`.dvpool`/`.dvdeck`形式(実体はzip)でエクスポート・
インポートでき、他のPC/exe配布先への持ち運びができる。カード画像そのものを
ブラウザ上で合成生成できる「オリカメーカー」も内蔵している(後述)。削除などの確認
ダイアログはブラウザ標準ではなくアプリ内の専用ポップアップ(Enterで決定・Escで
キャンセル・枠外クリックでキャンセル。ただしオリカメーカーだけは誤操作で編集内容を
失わないよう枠外クリックでは閉じない)。Node.js製の小さなローカルサーバー上で動作し、PWAとして
ブラウザ・デスクトップにインストールできる(スマホから同一Wi-Fi内のPCへLAN経由で
アクセスした場合、ブラウザのタブとしては普通に使えるが、ホーム画面への追加だけは
できない。平文httpのLAN IPが「secure context」にならないというブラウザの仕様による。
対応しないと決めた項目、詳細はCLAUDE.md)。

**注意:** カードプール管理・カードの登録/編集/削除(トリミング含む)・デッキビルダー
(複数プール参照)・デッキ表示・各種リネーム/複製/削除/並び替え・カード一覧の
一括削除は一通りブラウザ上で動作確認済み。モバイル実機からのLANアクセスは
実機が用意できないため未検証(同一PC上で同等の状況を作った検証では、アプリ自体は
LAN経由のhttpで問題なく動作し、PWAインストールだけがブラウザのsecure context
仕様上できないことを確認済み)。詳しい経緯・現状のTODOは
[CLAUDE.md](CLAUDE.md) を参照。

## 配布版(exe)で試す

Node.jsのインストールやコマンド操作なしで試したい場合は、実行ファイル1つで動く版がある。

**[Releases](https://github.com/satoa-may5/deck-viewer/releases/latest) から
`deck-viewer-<バージョン>.zip` をダウンロード**し、好きな場所に展開する。
展開してできる`deck-viewer-<バージョン>/`フォルダの中の`deck-viewer-<バージョン>.exe`を
ダブルクリックするだけで動く。起動すると既定のブラウザで自動的に
`http://localhost:3000` が開く。終了する場合は開いたコンソールウィンドウを閉じる。
exeを実行すると同じ場所に`data/`・`images/`フォルダが自動生成されカード情報・画像が
保存されるため(バラのexeファイル1つだけを配ると、それらがダウンロードフォルダ直下
などに散らかってしまう)、専用フォルダごとzipにして配っている。フォルダごと移動すれば
データも一緒に持っていける。

exeを作る側(開発者)は、依存パッケージをインストール後に:

```bash
npm run build:exe
```

で `dist/deck-viewer-<バージョン>/deck-viewer-<バージョン>.exe`
(package.jsonの`version`から自動で名前が決まる)と、それをそのままzip化した
`dist/deck-viewer-<バージョン>.zip` が生成される(Windows向け。内部でNode.js本体ごと
1ファイルに固めているため、実行側にNode.jsのインストールは不要。実体は
`tools/package-release.js`、pkgでのビルド→専用フォルダに配置→zip化までを1コマンドで
行う)。新しいバージョンを配布したい場合は、`package.json`の`version`を上げてから
ビルドし直し、生成された`.zip`を [Releases](https://github.com/satoa-may5/deck-viewer/releases)
に新しいタグで公開する(`gh release create v1.0.1 dist/deck-viewer-1.0.1.zip --title "v1.0.1"`
のように、`gh`コマンドかGitHub上の「Draft a new release」から)。ホーム画面右下の
バージョン表記(`GET /api/version`経由で取得)は`package.json`の`version`と自動的に
一致するので、手動で書き換える箇所はない。zipをメール/チャット等で直接送る形でも
問題ない(gitやコマンド操作は受け取る側には不要)。

ホーム画面は起動のたびにGitHubの最新Release(`GET /api/latest-release`、1時間
キャッシュ)と手元のバージョンを比較し、新しい方があれば画面上部にバナーで知らせる
(自動ダウンロード・自動差し替えはしない、押すとReleaseページが開くだけの簡易版)。
新しいバージョンを公開するタイミングでこちら側が特別に何かする必要はなく、
上記の手順でReleaseを作るだけで反映される。

あらかじめ用意したカードプールをホーム画面の「カードプールをインポート」から選べる
ようにしたい場合は、ホーム画面の「カードプールをエクスポート」ボタンで対象プールを
`.dvpool`ファイル(実体はzip)としてダウンロードし、このリポジトリの`pool-exports/`
フォルダに置いた上で、`node tools/build-pool-export-index.js`を実行して
`pool-exports/index.json`を更新してからcommit・pushする(この一覧ファイルを
生成し忘れると新しい`.dvpool`がインポート画面に出てこないので注意)。アプリは
「カードプールをインポート」を開くたびに、この`pool-exports/index.json`をGitHubから
直接取得し、選ぶとその場でGitHubから該当の`.dvpool`をダウンロードして取り込む。
exeにあらかじめ同梱する仕組みは無いため、`npm run build:exe`をやり直す必要はない
(リポジトリにpushした瞬間から、既に配布済みのexeでも次にインポートを開けば
最新の一覧が見える)。受け取った側はgit・コマンドいずれも不要で、「カードプールを
インポート」ボタンを押して一覧から選ぶだけで完結する(このリポジトリは現在public
なので、GitHub側の認証も不要)。

## セットアップ(開発者向け)

Node.js(LTS版)が必要。データベースや追加サービスは不要。

Node.jsが未インストールの場合:

```powershell
winget install OpenJS.NodeJS.LTS
```

(Windows以外の場合は [nodejs.org](https://nodejs.org/) からLTS版をインストール。
インストール後、ターミナルを開き直してから `node --version` で確認)

このフォルダで:

```bash
npm install
npm start
```

ブラウザで `http://localhost:3000` を開く。`server.js` を編集しながら開発する場合は
`npm start` の代わりに `npm run dev` を使うと、変更を検知して自動で再起動する
(`nodemon` 使用。監視対象は`server.js`のみ)。

同じWi-Fi内のスマホから使いたい場合は、PCのLAN IPアドレスを調べて
(`ipconfig` の IPv4アドレス)、スマホから `http://<そのIP>:3000` にアクセスする。

## 使い方

1. ホーム画面の「カードプール」タブを開き、一番上の点線の「＋ カードプールを作る」から
   カードをグループ分けするための「カードプール」を作成する(例: 収録弾ごと、購入
   ロットごとなど)。カードプール名を入力する個別ページに移動するので、右下の＋
   ボタンから手持ちカードを登録する。「カードを1枚追加する」「カードを複数枚追加する」
   「オリカを追加する」の3つから選べる。1枚追加の場合、ポップアップが開いたら画像
   エリアをクリックして画像を選択→さらに開くトリミング用ポップアップでパン/ズーム
   調整して「OK」→カード名(空欄可)を入力して「保存する」。カード番号は入力不要で、
   サーバー側で自動的に採番される。複数枚追加は選んだ画像をそのまま一括登録し
   (情報は後から個別に編集)、「オリカを追加する」はカード画像そのものを合成生成する
   オリカメーカーが開く(下記参照)。
2. ホーム画面の「デッキ」タブの「＋ デッキを作る」からビルダーを開き、上部で参照する
   カードプールを1つ以上選択すると、そのプールのカードが下に一覧表示される。
   タップ/スワイプして上のデッキにカードを追加し、デッキ名を入力して「保存」。
3. カードプール一覧の各行は左端のハンドルをドラッグして並び替えでき、★(お気に入り)/
   ✎(リネーム)/🗑(削除)のアイコンで操作できる(行をクリックすると個別ページを開く)。
   カードプールの削除は、そのプールに属するカードも一緒に削除される点に注意。
   デッキ一覧も同様にドラッグで並び替えでき、「表示」「編集」に加え★(お気に入り)・
   ⋮メニューから「リネーム」「複製」「削除」ができる。
4. カードプール個別ページの右上のトグル(☰/▦)で一覧表示・グリッド表示を切り替えられる。
   一覧表示はドラッグで並び替えができる。カードの画像をクリックすると編集モーダルが
   開き、名前や各種情報の変更・画像の差し替え・そのカードの削除ができる(名前を空欄の
   まま保存するとCARD-001のように自動で連番の名前が付く)。「選択して削除」で一括削除
   モードに入ると、グリッド表示ではチェックボックス、一覧表示では赤枠で複数選択して
   一括削除できる。
5. デッキ編集画面の「画像を出力」から画像出力画面に移ると、デッキ一覧を16:9の画像
   として保存できる(デッキ名・カード名・マナカーブの表示切り替え、中央揃え/左詰め、
   カードのドラッグ並び替えに対応)。「このデッキを印刷」からはA4に9枚ずつ並べた
   印刷用ファイルを作れる(下記参照)。
6. あらかじめ用意しておいたカードプールをホーム画面の「カードプールをインポート」
   から取り込める(このリポジトリの`pool-exports/`から一覧を取得する。詳細は開発者向け
   セクションの「配布版で試す」参照)。
   これとは別に、「カードプールをエクスポート」ボタンから任意のカードプールを
   `.dvpool`ファイル(zip)としてダウンロードでき、「カードプールをインポート」内の
   「＋ ローカルからカードプールをインポート」からそのファイルを選んで別PC/別exeへ
   取り込める。デッキも同様に、デッキ編集画面の☰メニューから`.dvdeck`として
   エクスポート/インポートでき(インポートは参照先カードを丸ごと新規プールとして
   複製するため、元のカードプールが無いPCでも成立する)、ホーム画面のデッキタブにも
   インポートボタンがある。exeを受け取って使う側は、いずれの操作もgit・コマンド
   操作いずれも不要で、アプリ内のボタン操作だけで完結する。

## デッキの画像出力・印刷

デッキ編集画面の「画像を出力」ボタンから移る画面(`deck-view.html`)で、2種類の
書き出しができる。

**画像として保存**: デッキ一覧を16:9の画像(1600×900)として書き出す。デッキ名・
カード名・マナカーブの表示はチェックボックスで切り替えられ、最後の行が埋まらない
ときの寄せ方(中央揃え/左詰め)も選べる。カードはこの画面上でドラッグして並び替え
られる(並び順はデッキに保存される)。表示設定は次回以降も保持される。

**このデッキを印刷**: A4に3×3の9枚ずつ、実寸(63mm×88mm)で並べた印刷用ファイルを
作る。切り出してプロキシにする用途。ポップアップで次を選ぶ。

- **形式**: TIFF(無圧縮・既定) / PNG(可逆圧縮)。どちらも1ページにつき1ファイル。
  セブン-イレブンのネットプリントはどちらも受け付ける。TIFFに対応していない印刷
  サービスもあるので、使う予定のサービスが分からない場合はPNGが確実
- **カードの大きさ**: 台紙のピクセル数は「カードが元画像と同じピクセル数で刷られる
  ように」逆算する(通常サイズ: カード600×838px → 台紙2000×2829px、約242 DPI)。
  デッキに2倍解像度のオリカが含まれるときだけ「高画質」(カード1200×1676px →
  台紙4000×5657px、約484 DPI)を選べ、その場合は高画質が既定になる
- 推定ファイルサイズを表示し、10MBを超えるとネットプリントが使えない可能性を警告する

**印刷サイズを調整**(キャリブレーション): プリンターやドライバの設定によって、実際に
印刷される大きさは指定どおりにならないことがある。「調整用シートをダウンロード」で
100mmの横線・縦線が入った1枚を印刷し、定規で実測した長さを入力して保存すると、
以降の印刷が正確に63mm×88mmになるよう自動で補正される。ずれ方は形式ごとに違うため、
補正値はTIFF/PNGで別々に保存する(画質の設定では変わらないので分けていない)。

## オリカメーカー

カードプール個別ページの＋ボタン →「オリカを追加する」で、カード画像そのものを
ブラウザ上で合成生成できる(`public/oricard/`。元は別プロジェクトとして作られた
スタンドアロンのツールで、iframeとして埋め込んでいる)。「カード情報」(色・種類・
必要エナジー・消費AP・カード名・特徴・トリガー・レイド・BP)「イラスト」「効果テキスト」
の3タブ構成で、入力すると右側のプレビューにリアルタイムで反映される。カードの下地は
「通常」と「SR」の2種類から選べる(SRはイラスト枠が縦に大きく[524×640]、イラストを
2枚重ねられ、効果テキストが最大12行まで下揃えで伸びる)。

書き出しは常に**2倍解像度(1200×1674px)**で行う(印刷したときの粗さを減らすため。
設定項目はない)。

効果テキストにはインラインアイコン(トリガー種別・エナ玉など)を素材ボタンから挿入
できるほか、「テンプレート」からよく使う一文をまるごと貼り付けられる。アイコンは
`[[登場時]]`のような独自記法で保持され、**カードプールに登録する時点で他のカードと
同じ表記(`[登場時]`など)に自動変換される**(オリカメーカー内の入力欄は独自記法の
まま)。エナジー玉は個数がそのまま数字になる(2個並べれば`2`)。

イラストは「カードイラスト」「カード名イラスト」「背景イラスト」「テキストエリア
イラスト」の4スロットに個別の画像をドラッグ&ドロップででき、それぞれズーム/位置を
調整できる(配置領域は各マスク素材の不透明部分から自動的に決まる。SRテンプレートでは
「カードイラスト1」がカード全面、「カードイラスト2」が枠内、テキストエリアイラストは
無し、という構成になる)。カード名の枠は色と明度を自由に変更できる。各スロットの
見出しの横にあるボタンから、「この大きさで画像を作ればぴったり入る」というサイズの
テンプレートPNGをダウンロードできる。

「このカードを追加する」でその場のプレビュー内容がPNG化され、フォームに入力した情報
(色・タイプ・必要エナジー・特徴・効果など)ごと新規カードとしてそのカードプールに
登録される。同じ行の左側にはPNG単体保存・JSON保存/読込のボタンがある。

登録したオリカは**あとから作り直せる**。カード一覧で画像をクリックして開く「カードを
編集」モーダルの「オリカメーカーで編集」を押すと、そのカードを作ったときの設定
(イラストや入力内容)ごとメーカーが開く。設定は`data/oricard-states/`に1枚ずつ
保存されている。

プレビュー下の「カードプールにこのスタイルを保存」を押すと、カード名イラスト・枠の
色/明度・背景イラスト・テキストエリアイラストがそのカードプールに保存され、次に同じ
プールでオリカメーカーを開いたときに自動的に適用される(シリーズで見た目を揃えたい
場合に使う)。保存したスタイルはカードプール個別ページの右側、「サムネイルを設定」の
下に「カードスタイル」としてプレビュー付きで表示され、そこをクリックすると
**スタイルに含まれる項目だけ**を編集する専用画面が開く(カード1枚ごとの情報は
出てこない)。同じ画面から「スタイルを解除」もできる。

## 画像について

カード画像自体(スキャン/撮影データ)は著作権の関係もあるため `.gitignore` で除外している。
**カード情報(`data/cards.json`・`data/cardpools.json`・`data/decks/*`・
`data/oricard-states/*`)もgit管理外**(公開リポジトリなので、個人の使用データを
載せないため)。そのため `git clone` した直後はカードプールもカードも0件の状態で、
`server.js` が空のファイルを自動生成する。まず「カードプール」タブから作成して
試すところから始める。

**PC間でデータを持ち運ぶ場合はgitではなく、アプリの`.dvpool`/`.dvdeck`
エクスポート/インポートを使う**(画像も一緒に入るので、これだけで完結する)。
