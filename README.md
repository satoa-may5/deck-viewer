# deck-viewer(デッキメーカー(仮))

手持ちのカード画像からデッキのカード一覧を作れるローカルアプリ。カードは
「カードプール」(弾ごとなどのグループ)単位で登録し、デッキ作成時は1つ以上の
カードプールを参照して手持ち一覧を組み立てる。カードの登録(画像アップロード+
トリミング+情報入力)・編集・削除、Shadowverse風のデッキビルダー、Bandai TCG+ 風の
読み取り専用デッキ表示を備える。ホーム画面は「デッキ」「カードプール」のタブ切り替えで、
どちらも削除・並び替え(ドラッグ、一覧/グリッド表示両対応・デフォルトはグリッド)、
お気に入り登録(★、「お気に入りのみ表示」で絞り込みも可)ができ、デッキはさらに
リネーム・複製もできる。カードプール・デッキにはそれぞれ1枚までサムネイル画像を
指定でき、名前は重複すると自動で「(1)」のように連番が付く。カードにはタイプ
(キャラクター/イベント/フィールド)・必要エナジー・色・パラレルの有無・トリガー
(カード画像から自動判定可能)を設定でき、カードプール個別ページ・デッキ作成画面
どちらでもこれらの条件で絞り込める。カードプール・デッキはそれぞれ`.dvpool`/
`.dvdeck`形式(実体はzip)でエクスポート・インポートでき、他のPC/exe配布先への
持ち運びができる。削除などの確認ダイアログはブラウザ標準ではなくアプリ内の専用
ポップアップ(Enterで決定・Escでキャンセル・枠外クリックでキャンセル)。Node.js製の
小さなローカルサーバー上で動作し、PWAとしてブラウザ・デスクトップにインストールできる
(モバイルのLAN経由インストールはブラウザのsecure context仕様上不可、詳細はCLAUDE.md)。

**注意:** カードプール管理・カードの登録/編集/削除(トリミング含む)・デッキビルダー
(複数プール参照)・デッキ表示・各種リネーム/複製/削除/並び替え・カード一覧の
一括削除は一通りブラウザ上でスクリーンショット込みで動作確認済み。またモバイル
実機からのLANアクセス・PWAインストールはまだ未検証。詳しい経緯・現状のTODOは
[CLAUDE.md](CLAUDE.md) を参照。

## 配布版(exe)で試す

Node.jsのインストールやコマンド操作なしで試したい場合は、`dist/deck-viewer.exe`
(下記の手順でビルドしたもの)をそのままダブルクリックするだけで動く。起動すると
既定のブラウザで自動的に `http://localhost:3000` が開く。終了する場合は開いた
コンソールウィンドウを閉じる。exeと同じ場所に`data/`・`images/`フォルダが自動生成
され、そこにカード情報・画像が保存される(exeを別の場所に移すとデータも一緒に
持っていく必要がある)。

exeを作る側(開発者)は、依存パッケージをインストール後に:

```bash
npm run build:exe
```

で `dist/deck-viewer.exe` が生成される(Windows向け。内部でNode.js本体ごと1ファイルに
固めているため、実行側にNode.jsのインストールは不要)。この`dist/exe`本体を渡したい
相手に直接送るだけでよい(gitやコマンド操作は不要)。

あらかじめ用意したカードプールを同梱したい場合、2通りのやり方がある。

- **手持ちの画像フォルダから作る場合**: `pool-exports/<好きな名前>/images/` に画像
  ファイル(png/jpg)を入れるだけでよい。設定ファイルは必須ではなく、無ければ
  カードプール名はフォルダ名、カード名は各画像のファイル名(拡張子を除いたもの)が
  そのまま使われる。カード名やプール名を個別に指定したい場合だけ、同じフォルダに
  `manifest.json` を置く:
  ```json
  {
    "poolName": "カードプールの表示名",
    "cards": [
      { "image": "001.png", "name": "カード名を指定したい場合だけ書く", "cost": 3, "color": "青", "parallel": true, "type": "character" },
      { "image": "002.png" }
    ]
  }
  ```
  `cards`を書かない場合は`images/`内の全画像がファイル名順に使われ、`name`を省略
  した項目は画像のファイル名がそのままカード名になる。`cost`(必要エナジー)・
  `color`(色)・`parallel`(パラレルかどうか)・`type`(`character`/`event`/`field`の
  いずれか)はいずれも省略可(それぞれ`null`・空文字・`false`・空文字扱い。`type`に
  上記3つ以外の値を書いても無視され空扱いになる)。
- **アプリに登録済みのプールから作る場合**: 通常の`npm start`/`npm run dev`で
  動かした状態で対象プールに対して
  `curl -X POST http://localhost:3000/api/pools/<プールID>/export` を実行すると、
  そのプールのカード名・画像から`pool-exports/<プールID>/`が自動生成される。

どちらの場合も、`pool-exports/`は`public/`と同様に`npm run build:exe`でexeへ静的に
同梱されるため、受け取った側はホーム画面の「カードプールをインポート」ボタンを
押すだけで(git・コマンド不要)取り込める。

## セットアップ(開発者向け)

Node.js(LTS版)が必要。データベースや追加サービスは不要。

Node.jsが未インストールの場合:

```powershell
winget install OpenJS.NodeJS.LTS
```

(Windows以外の場合は [nodejs.org](https://nodejs.org/) からLTS版をインストール。
インストール後、ターミナルを開き直してから `node --version` で確認)

このフォルダで:

```bash
npm install
npm start
```

ブラウザで `http://localhost:3000` を開く。`server.js` を編集しながら開発する場合は
`npm start` の代わりに `npm run dev` を使うと、変更を検知して自動で再起動する
(`nodemon` 使用。監視対象は`server.js`のみ)。

同じWi-Fi内のスマホから使いたい場合は、PCのLAN IPアドレスを調べて
(`ipconfig` の IPv4アドレス)、スマホから `http://<そのIP>:3000` にアクセスする。

## フォルダ構成

```
deck-viewer/
├── server.js          Expressサーバー本体(静的配信 + API)
├── data/
│   ├── cards.json       登録済みカードのデータベース(各カードは1つのプールに属する。
│   │                    IDはサーバー側で自動採番)
│   ├── cardpools.json   カードプール(グループ)のデータベース(配列の並び順=表示順)
│   └── decks/*.json     保存したデッキ(参照するプールのIDと表示順を保持)
├── images/             カード画像(git管理外。各自で用意する)
├── pool-exports/       あらかじめ用意したインポート用カードプール(`<名前>/images/`に
│                      画像を置くだけ、または`manifest.json`で名前を指定して用意し、
│                      `npm run build:exe`でexeに同梱する。詳細は「配布版で試す」参照)
└── public/              フロントエンド
    ├── index.html       ホーム(「デッキ」「カードプール」タブ切り替え。各タブに
    │                    ＋作成行、削除・並び替え・★お気に入り(絞り込み込み)・
    │                    エクスポート/インポート。デッキはさらにリネーム/複製、
    │                    カードプールはさらに✎リネーム)
    ├── pool-detail.html  カードプール個別ページ(名前編集+カード一覧[一覧/グリッド表示
    │                    切り替え可]+カード追加モーダル[画像入力→トリミングポップアップ
    │                    →カード名(任意)入力])
    ├── builder.html      デッキビルダー(参照プールを選択→タップ/スワイプでカードを追加)
    └── deck-view.html     デッキの読み取り専用表示
```

## 使い方

1. ホーム画面の「カードプール」タブを開き、一番上の点線の「＋ カードプールを作る」から
   カードをグループ分けするための「カードプール」を作成する(例: 収録弾ごと、購入
   ロットごとなど)。カードプール名を入力する個別ページに移動するので、右下の＋
   ボタンから手持ちカードを登録する。ポップアップが開いたら画像エリアをクリックして
   画像を選択→さらに開くトリミング用ポップアップでパン/ズーム調整して「OK」→
   カード名(空欄可)を入力して「保存する」。カード番号は入力不要で、サーバー側で
   自動的に採番される。
2. ホーム画面の「デッキ」タブの「＋ デッキを作る」からビルダーを開き、上部で参照する
   カードプールを1つ以上選択すると、そのプールのカードが下に一覧表示される。
   タップ/スワイプして上のデッキにカードを追加し、デッキ名を入力して「保存」。
3. カードプール一覧の各行は左端のハンドルをドラッグして並び替えでき、★(お気に入り)/
   ✎(リネーム)/🗑(削除)のアイコンで操作できる(行をクリックすると個別ページを開く)。
   カードプールの削除は、そのプールに属するカードも一緒に削除される点に注意。
   デッキ一覧も同様にドラッグで並び替えでき、「表示」「編集」に加え★(お気に入り)・
   ⋮メニューから「リネーム」「複製」「削除」ができる。
4. カードプール個別ページの右上のトグル(☰/▦)で一覧表示・グリッド表示を切り替えられる。
   一覧表示はドラッグで並び替えができる。カードの画像をクリックすると編集モーダルが
   開き、名前の変更や画像の差し替えができる(名前を空欄のまま保存するとCARD-001の
   ように自動で連番の名前が付く)。「選択して削除」で一括削除モードに入ると、
   グリッド表示ではチェックボックス、一覧表示では赤枠で複数選択して一括削除できる。
5. あらかじめ用意しておいたカードプールをホーム画面の「カードプールをインポート」
   から取り込める(exeに同梱する仕組みは開発者向けで、下記「配布版で試す」参照)。
   これとは別に、「カードプールをエクスポート」ボタンから任意のカードプールを
   `.dvpool`ファイル(zip)としてダウンロードでき、「カードプールをインポート」内の
   「＋ ローカルからカードプールをインポート」からそのファイルを選んで別PC/別exeへ
   取り込める。デッキも同様に、デッキ編集画面の☰メニューから`.dvdeck`として
   エクスポート/インポートでき(インポートは参照先カードを丸ごと新規プールとして
   複製するため、元のカードプールが無いPCでも成立する)、ホーム画面のデッキタブにも
   インポートボタンがある。exeを受け取って使う側は、いずれの操作もgit・コマンド
   操作いずれも不要で、アプリ内のボタン操作だけで完結する。

## 画像について

カード画像自体(スキャン/撮影データ)は著作権の関係もあるため `.gitignore` で除外している。
`data/cards.json` や `data/decks/*.json` は通常のテキストなのでgit管理に含めており、
他のPCで `git clone` すればカード情報・デッキ情報は引き継がれる(画像だけは別途用意)。
リポジトリ自体は空のデータ(`data/cards.json`・`data/cardpools.json`は空配列)から
始まるので、`git clone` した直後はカードプールもカードも0件の状態。まず「カードプール」
タブから作成して試すところから始める。
